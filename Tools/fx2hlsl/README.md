# fx2hlsl

One-time conversion of the DX11 Effects (`.fx`) shaders in
`LibXLT/GraphicsDX11/Eff/private/Shaders` to plain HLSL, as the first step in
removing the Effects (FX11) dependency. Each `Foo.fx` becomes:

- **`Foo.hlsl`**: the original source with only Effects-only syntax removed.
  - `technique11`/`pass` blocks are deleted.
  - `SamplerState { ... }` initializers are deleted; the declaration stays.
  - `< ... >` annotation blocks are deleted.

  When a pass called a shader function with uniform arguments (`compile ps_5_0 Blur(HPixelOffsets, downsampledTexture, ...)`), a small entry point that makes that call is appended. Every stage can then be compiled on its own with `fxc /T ps_5_0 /E <entry>` or with dxc.
- **`Foo.effect.json`**: what the Effects runtime used to read from the `.fx`.
  - Techniques, mapped to passes, mapped to per-stage entry point and profile. A stage that a pass explicitly set to `NULL` is recorded as `null`; a stage the pass never mentioned is absent.
  - Sampler state descriptions.
  - Global variables with their semantic, annotations (the SAS material-UI metadata) and default value. Plain HLSL ignores initializers on globals, so the runtime has to apply these defaults.

Local `#include` files (`Support.h`, `Lighting.h`, ...) are converted the same
way to `.hlsli`, and the `#include` lines are rewritten to point at them.

The shader math is left untouched. Techniques, function signatures and
variables are read from a preprocessed copy, so passes generated by macros
(`PASS_DEFAULT(Tess)`) are found. The rewrite itself only deletes spans of the
original text, so comments and macros survive.

This is a one-time tool. After a file is converted, the `.hlsl` is the source
of truth and is edited by hand; the tool is not part of the build.

## Usage

```
python -m pip install pcpp
cd LibXLT/GraphicsDX11/Eff/private/Shaders
python ../../../../../Tools/fx2hlsl/fx2hlsl.py --root . Special/Blur.fx
python ../../../../../Tools/fx2hlsl/fx2hlsl.py --root . --check $(ls *.fx)   # parse only
```

`compile_check.py` compiles every entry point listed in one or more manifests:

```
python Tools/fx2hlsl/compile_check.py --compiler fxc --exe <path to fxc.exe> Special/Blur.effect.json
python Tools/fx2hlsl/compile_check.py --compiler dxc Special/Blur.effect.json            # SM 6.0
python Tools/fx2hlsl/compile_check.py --compiler dxc --spirv Special/Blur.effect.json    # Vulkan
```

CI compiles every `*.effect.json` under `LibXLT` as SM 5 (fxc) and as SM 6 (dxc), both from the Windows SDK. A converted file is not done until it passes both.

## Current coverage (dry run on all 60 `.fx` files)

- All 60 files parse and convert, covering every technique and pass.
- Under dxc (SM 6.0), 20 of the 60 files compile cleanly as converted.
- Most of the rest stop on legacy D3D9 keywords that fxc accepts but dxc does not, mainly `sampler2D` in `Tessellate.h` and `texture2D` in a few effects. Those get fixed when each file is converted, since every converted file has to pass both SM 5 and SM 6.
