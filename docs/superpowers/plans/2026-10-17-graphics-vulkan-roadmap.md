# GraphicsVulkan Phase 1 — roadmap of plans

**Spec:** `docs/superpowers/specs/2026-10-17-graphics-vulkan-design.md`

Phase 1 is too large for one plan, and later plans depend on what earlier
ones learn (the descriptor model, the device layer's shape, how faithful
the first images are). Each plan below produces working, testable software
on its own, and every plan must leave Vulkan validation clean (spec, "Validation"). The owner reviews each finished plan before the next is written or started. Only Plan 1 is written in detail. Plans 2–7 are stubs (scope, exit criteria, open questions); each is detailed when the previous one is finished and reviewed, from the spec plus what was learned.

## Status

- **Plan 1: done** (2026-10-17; `0f415493`..`ac724e7b`, flag reference `cec88868`).
- **Plan 2: done** (2026-10-18; `8446cfd8`..`f1daf918`, plus the final-review fix), reviewed.
  - **Descriptor model, decided:** `VK_EXT_descriptor_heap`. Per draw, a binding table in the ring buffer (constant-buffer addresses, then texture, sampler and UAV heap indices by DX11 register slot); its address goes in with `vkCmdPushDataEXT`; DXC's `-fvk-[btsu]-shift` bindings map onto it, so the HLSL stays unchanged. Verified on the Quadro RTX 5000 (driver 596.59) with core, sync and GPU-assisted validation clean (`vkdBindingsTest`). The spec's fallbacks (descriptor buffers, push descriptors) weren't needed. Details in `vkd/vkdBindings.hpp`.
  - **Validation:** 0 errors and 0 warnings in the unit tests and in Qt/Wx/RenderNode start-up and shutdown, Debug and Release (`-gfxValidation`). The Intel UHD P630 is refused (it lacks Vulkan 1.4 and `VK_EXT_descriptor_heap`).
  - **For later plans:**
    - Every hook not yet ported is a stub that logs `GVK_NOT_YET`.
    - Rendering the test scene with `-gfx vulkan` stops at model loading, because `mdlFragCreateVk::CreateFragment` returns empty fragments (subdivision surfaces then find no vertices). Plan 4's real fragments fix this. Stub fragments already match DX11's format: `BumpTex1Vertex`, 16-bit indices unless `g3dIndexPtr::Needs32Bit`.
    - RenderNode with `-new` never exits, on DX11 as well (existing behaviour). Use `-version` for a start-up/shutdown check.
    - The Release DX11 frames are unchanged from Plan 1 (135/135).
- **Plan 3: done** (2026-10-18; `1196543a`..`b1bacd38` plus the docs commit), waiting for the owner's review. Plan 4 is written and split into 4a (textures) and 4b (first scene), each with its own review.
  - **Shaders:** a byte-identical copy of GraphicsDX11's, compiled to SPIR-V at build time by `EmbedShadersVk.ps1`: 60 effects, 753 of 756 stages (`Hair_HS` deferred to Plan 7: 62 passes). DXC options: `-spirv -fspv-target-env=vulkan1.3 -fvk-use-dx-layout -fvk-use-dx-position-w -fvk-support-nonzero-base-instance -fvk-support-nonzero-base-vertex -fvk-[btsu]-shift 0/100/200/300`; Y flipped by a negative viewport height. CI compiles them with `compile_check.py --spirv`.
  - **Reflection:** `fxEffectVk` reports every effect exactly as `fxEffectDX11` does (names, buffers, offsets, sizes, matrix majorness, types, defaults, registers per stage), with no exceptions (`fxEffectVkReflectionTest`); the fxEffect API (`effPlainEffectVk`) behaves like DX11's for every effect (`effPlainEffectVkTest`).
  - **Images:** 78 full-screen effect passes drawn by both backends from the same inputs: 56 bit-exact, 22 within 1/255 (`fxParityTest`); the full-screen quad matches; `vkdContext` puts pixels, winding and culling exactly where D3D11 does.
  - **New required features:** `scalarBlockLayout` (D3D constant buffer packing), the shaders' SPIR-V capabilities (`shaderImageGatherExtended`, `shaderClipDistance`, `shaderDrawParameters`, `shaderDemoteToHelperInvocation`) and the fixed-function ones the port needs (anisotropy, mirror-once, wireframe, depth clamp, depth bias clamp, independent and dual-source blend, BC textures, cube arrays).
  - **Validation:** 0/0 in all tests (750) and a whole-suite GPU-assisted run. `WARNING-Shader-OutputNotConsumed` (valid usage, from the unchanged shaders) is logged as information. Owner's decision (2026-10-18): fix it at the end of the port (Plan 7), not before.
  - **Owner's decisions for Plan 4 (2026-10-18):** no DirectXTex or WIC in GraphicsVulkan (stb_image, libtiff, and tinyddsloader vendored in `3rdParty/`); libtiff from vcpkg for both backends, and `3rdParty`'s copy removed.
  - **For later plans:** fonts moved to Plan 4; the material shader classes are Plan 4's first job, on `effPlainEffectVk`. One binding table serves all stages where D3D11 had per-stage registers: `fxEffectVk::Apply` logs a pass whose stages want different things in one register (none seen yet). The pipeline cache lives in the user data folder.
- **Plan 4a: done** (2026-10-19; `8bacbe03`..`d5b89c83` plus the docs commit), waiting for the owner's review.
  - **libtiff:** from vcpkg (4.7.1) for both backends; `3rdParty/tiff-4.0.6` removed. libtiff and the DLLs it brings are pinned to the same versions in GraphicsVulkan's, GraphicsDX11's and GraphicsTests' manifests; zlib to MainApp's 1.3.1.
  - **Images:** `vkdImage` covers every shape (1D/2D/3D, arrays, cubes, mips, multisampling) with upload, readback and mip generation; `vkdBuffer`; `vkdFormat` maps DXGI formats. The only substitutions are B8G8R8X8 and its sRGB form (Vulkan has no X8 formats): B8G8R8A8 with alpha 255.
  - **Decoding, no DirectXTex or WIC:** stb_image (PNG, JPEG, GIF, paletted/RLE BMP), libtiff, and ports of DirectXTex's DDS and TGA readers (including the legacy-DDS conversions) and of Graphics' RGBE reader; uncompressed 24/32-bit BMPs are read from their bit masks. The owner kept the DDS port instead of tinyddsloader (2026-10-18). Against DirectXTex on the CPU (`DecodeMatchesDirectXTex`): every PNG, BMP, GIF, TGA, TIFF, HDR and DDS file byte-exact; JPEG within 2/255 (WIC and stb_image differ in IDCT and chroma upsampling).
  - **Mips:** DirectXTex's triangle and box filters ported, and WIC's Fant scaler (8-bit mips and reductions) emulated from measurements; 0/255 against DirectXTex everywhere tested.
  - **Textures on the GPU (`matTextureMgrVkTest`, both layers through `gtBackend`):** 110 of the 115 generated files load on both (the other 5 load on neither) and every texel matches DX11 exactly (0/255) for PNG, BMP, TGA, TIFF, HDR and DDS, at every mip, reduced, cube face and volume slice; create, fill, update, copy, render-target clear, draw and resolve also match exactly. JPEG is the one exception: max 2/255 (any share of pixels), and 4/255 through an sRGB format.
  - **Where Vulkan differs from DX11 on purpose:** DX11 crashes or fails on some loads (a no-mip load asks DirectXTex for a one-level chain, which it rejects; a TGA or HDR it can't decode is dereferenced); Vulkan loads the one-level texture or reports a missing texture. The demo watermark (a Windows resource texture) isn't loaded. Shadow maps, RSMs and cube render targets are textures with a size and no image until Plan 5; `MergeTransparentTextures` and saving textures wait for Plan 6.
  - **Validation:** 0/0 in all tests (776 Debug, 775 Release) and a whole-suite GPU-assisted run; `-gfx vulkan` start and quit in RenderNode and Qt, Debug and Release: 0/0. DX11 frames unchanged from Plan 1 (135/135).
  - **For Plan 4b:** `gtBackend` runs a test under each whole layer, so 4b's scene tests can compare DX11 and Vulkan through Graphics calls. `g2dSystemVk` now deletes the reset handlers, as DX11 does. Debug GraphicsTests reports two small leaks at exit that don't come from the port (Core's resource-tracker list, one DX11 render target); `g2dResetHandler` has no virtual destructor.
- **Plan 4b: done** (2026-10-19; `394259a0`..`7b477945` plus the docs commit), waiting for the owner's review. With 4a, Plan 4 is done.
  - **Ported:** tmesh and bump fragments and the bump renderer (static buffers device-local, dynamic ones written to the ring per use; 32-bit indices above 65,535 vertices; draw-limit splits); every material shader class (`effShaderBaseVk`, the 15 `eff*` classes, `effShaderArray`'s registration); the per-node rendering machinery and the forward renderer `g3dSceneRendererVk`; windows that render scenes (swap chain or offscreen at a render resolution; `DrawImage`, `DrawRect`); fonts. Pulled forward because the test scene needed them: `may` fragment creation (Plan 6), cube render-target textures (Plan 5; nothing fills them yet), and from Plan 6 frame capture (`g2dScreenCaptureUtilVk`), RGBA-float `GetPixels` and image saving (EXR, HDR, TGA through Graphics' writers; PNG through stb_image_write; BMP, JPG, TIFF and DDS still `GVK_NOT_YET`).
  - **Parity (GraphicsTests, both layers through `gtBackend`):** fragments' vertex and index bytes identical; material constants and texture bindings byte-identical for Blinn, Phong, Lambert and the built-ins, including zero, all-zero and 1e6 values; forward-renderer scenes: lit spheres and textured 1/255, transparency 0, fog 1/255 (neither forward renderer applies fog), wireframe and lit wireframe 0, tessellated 0, large and split meshes within tolerance; scene in a window equal to offscreen (0/255); `DrawImage` 0 differing pixels; text 0/255 in windows and render targets; cube render targets, window/offscreen/render-target captures and saved PNGs identical to DX11. No loosened tolerances.
  - **Rasterization:** D3D11 draws lines from multisample-enabled states as 1.4-pixel quads: matched with rectangular lines of width 1.4 (now required features: `rectangularLines`, `bresenhamLines`, `wideLines`).
  - **Fixed on the way:** a swap chain's acquire semaphore was waited only by `Present`'s submission, so a submission mid-frame (a capture readback) wrote the image unwaited; `vkdDevice::AddSubmitWait` hands it to whichever submission comes first. A window whose native client area isn't the size it was given (RenderNode's 1920x1080 capture window on a 1920x1080 screen) renders offscreen at that size and is stretched in `Present`, as D3D11's `ResizeBuffers` and DXGI do. DXC gets `-fvk-auto-shift-bindings` (the font shaders have no `register()`; every other effect's SPIR-V unchanged).
  - **MachStudio on Vulkan:** the test scene loads and shows in the Qt viewport (Debug and Release) through the forward stand-in; orbit, zoom, panel layouts, resizes and minimize/restore are clean. RenderNode with `-gfx vulkan -gfxValidation` writes all 135 frames, Debug (with `-gfxProfile`: a timing CSV) and Release. The frames are a smoke test (no HDR, shadows, tone mapping or `shdw` material passes), not parity.
  - **Validation:** 0/0 in all tests (Debug 802, Release 801), the Qt sessions and the RenderNode render. DX11 frames unchanged from Plan 1 (135/135).
  - **`GVK_NOT_YET` seen in MachStudio:** every renderer type but the forward one (default/shdw, HDR, AO, GI, cube map, planar reflection, depth, glow, illumination, materials, normal, reflection-only, shadow mask, UV, velocity), the pick renderer, resource counters. Elsewhere in the code: shadow maps and RSMs, `CopyWithResolve`'s scaled and depth copies, `MergeTransparentTextures`, texture saving, image resampling and loading, BMP/JPG/TIFF/DDS saving, baking, hair (Plan 7), the window debug overlay, instance step rates above 1.
  - **For Plan 5:** test-scene parity is Plan 5's (decision 1); its first job is the `shdw` creator replacing the forward fallback. (The DX11 child processes 4b's tests used are gone: see the test speed-up below.)
- **Test speed-up (between 4b and 5): done** (2026-10-19), waiting for the owner's review.
  - **GraphicsTests:** Debug 270 s to 41 s, Release 150 s to 12 s, in the build's post-build step (802 / 801 tests, all passing, validation 0/0).
    - No child processes: the DX11 crash after a font load was the test harness starting and stopping COM around each DX11 run while DirectXTex keeps one WIC factory per process; COM now starts once per run (`gtPlatform::StartCom`), as in MachStudio. GraphicsDX11's forward renderer now clears its transparent-node list after drawing it (it kept every node it was ever given and drew freed ones again; a one-line fix, as `g3dSceneRendererVk` already did). `gtDx11Child` is removed.
    - The three parameterized suites (660 tests) share devices per suite: `fxEffectVkReflection` and `effPlainEffectVkTest` build each effect pair once on one D3D11 device; `fxParity` uses `gtVulkanSuite` (one Vulkan device and context per suite, validation checked per test and at device destruction). 95 s to 10 s in Debug.
    - `bumpFragmentVkTest` runs each test's cases under one layer start-up per backend (27 s to 12 s).
    - The post-build step runs `UnitTests/RunShards.ps1`: up to 8 gtest shards at once (each with its own user data folder), XML merged.
  - **Short test-scene runs:** MachStudio's `-capStartFrame` / `-capEndFrame` (absolute frame numbers, both included) narrow any render's frame range; capture drivers still pick cameras within it, and file names keep the absolute numbers. A window starting after the range's start also renders the frame before it, unsaved, so motion-dependent output matches a full render (frames 400-404 alone: 5/5 identical to Plan 1's full run; without it the first frame differed by up to 64/255). `RenderJitteredFrame` no longer dereferences the missing image of a frame before the start time (a lead-in with jittered sampling crashed the same way). gfxcompare passes `--start-frame` / `--end-frame` to RenderNode and compares only that window, so a short run compares against Plan 1's full 135-frame reference: frames 296-315 on DX11, 20/20, in about a minute per render.
